University LMSIn development

  • React
  • TypeScript
  • Node.js
  • Express
  • PostgreSQL
Overview
A learning management system where students, lecturers and administrators each see only the parts of the system that concern them.
Approach
The backend is organised into models, controllers, routes and middleware. Role-based access control, request validation and centralised error handling are enforced there, and the React client mirrors those boundaries with an auth context and protected routes.
Key decision
Permissions are checked on the server first, and the client only reflects them. Hiding a page in the interface does not protect the data behind it, so the access rules live in backend middleware.

Task Manager

  • React
  • Express
  • MongoDB Atlas
  • Render
View live app
Overview
A task tracker modelled on the daily tracking I used to maintain by hand in my operations role.
Approach
A React client talks to an Express REST API that supports full create, read, update and delete, backed by a cloud-hosted MongoDB database. The whole stack is deployed and publicly accessible.
Key decision
The data lives in MongoDB Atlas instead of a local database. The API runs on Render, so a database on my own machine would be unreachable from the deployed app.

Velvet Vogue

  • HTML
  • CSS
  • JavaScript
View live site
Overview
A responsive fashion store of 15 pages, with search, filters, a wishlist, a promo-code cart and validated checkout.
Approach
All data access goes through a single layer, so the in-browser backend can be replaced by a real API without rewriting the pages. Keyboard navigation and visible focus states are built in throughout.
Key decision
Every read and write goes through one data layer, and no page touches storage directly. Moving to a real REST API then means changing one module instead of fifteen pages.
